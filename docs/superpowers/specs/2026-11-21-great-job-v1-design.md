# Great Job v1 — เอกสารออกแบบ

วันที่: 2026-11-21 · สถานะ: อนุมัติแล้ว

## 1. เจตนาและเหตุผล

Product ผู้ช่วยหางานแบบ AI agent สำหรับ **คนไทยสายเทคที่หางานในไทยและ remote ต่างประเทศ**
ดูแลตั้งแต่หางาน ประเมินงาน ติดตามสถานะ ไปจนถึงช่วยสมัคร โดยมี mascot ผีน้อยเป็นหน้าตาของ AI

เอกสารนี้ครอบคลุม **เวอร์ชันแรก (v1)** = ก้อน 1–3 ของแผนใหญ่:

| ก้อน | เนื้อหา | อยู่ใน v1 |
|---|---|---|
| 1 | เว็บ: สมาชิก, profile, list งาน, คะแนน, ghost job, ดึงงานอัตโนมัติ | ใช่ |
| 2 | Browser extension: เก็บงาน, แสดงคะแนนบนหน้าเว็บงาน, กรอกฟอร์ม | ใช่ |
| 3 | Mascot ผีน้อย | ใช่ |
| 4 | ที่ปรึกษา: แชต, ซ้อมสัมภาษณ์, ต่อรองเงินเดือน | ไม่ (เอกสารถัดไป) |
| 5 | สมัครอัตโนมัติฝั่ง server, เชื่อม Gmail ติดตามผล | ไม่ |
| 6 | ระบบจ่ายเงินและโควตา AI | ไม่ |

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- ผู้ใช้อัปโหลด resume ครั้งเดียว แล้วได้ list งานที่ AI คัดและให้คะแนนใหม่ทุกวันโดยไม่ต้องทำอะไร
- เปิดหน้างานบน JobsDB / JobThai / LinkedIn แล้วเห็นคะแนนและคำเตือน ghost job ทันที เก็บเข้า list ได้ในคลิกเดียว
- กรอกฟอร์มสมัครงานให้อัตโนมัติ ผู้ใช้ตรวจแล้วกดส่งเอง
- list งานแสดงสถานะตั้งแต่ "เจอแล้ว" ถึง "ได้ offer" ในที่เดียว
- ใช้ได้ทั้งไทยและอังกฤษ ใช้บนมือถือได้ (เว็บ)

**ไม่ใช่เป้าหมายของ v1**
- แชตที่ปรึกษา ซ้อมสัมภาษณ์ ต่อรองเงินเดือน
- การส่งใบสมัครโดยไม่มีคนกด
- การอ่านอีเมลของผู้ใช้
- เก็บเงิน
- แอปใน App Store / Play Store

**ถือว่าล้มเหลวแม้ทำงานได้ (anti-goals)**
- ส่งใบสมัครในชื่อผู้ใช้โดยเขาไม่ได้กดเอง
- เก็บรหัสผ่านเว็บงานของผู้ใช้ หรือทำอะไรที่ทำให้บัญชีเขาเสี่ยงโดนแบน
- Scrape JobsDB / JobThai / LinkedIn จาก server
- AI แต่งประสบการณ์หรือทักษะที่ผู้ใช้ไม่มีลงใน resume หรือคำตอบฟอร์ม
- บอกว่างานเป็น ghost job แบบฟันธงโดยไม่แสดงเหตุผล

## 3. ข้อจำกัดที่ตรวจแล้ว

ตรวจเมื่อ 2026-11-21 บางข้อมาจากข้อความสรุปของหน้าทางการ ไม่ได้อ่านต้นฉบับเต็ม
**ผู้สร้างต้องอ่านข้อตกลงฉบับจริงของแต่ละแหล่งก่อนเปิดใช้แหล่งนั้น**

- **Greenhouse / Lever / Ashby**: ข้อมูลประกาศงานอ่านได้โดยไม่ต้องมี key
  การ *ส่ง* ใบสมัครผ่าน API ต้องใช้ key ของนายจ้างทุกเจ้า → ฝั่ง server สมัครแทนผู้ใช้ผ่าน API ไม่ได้
  ทางเดียวคือกรอกฟอร์มในเบราว์เซอร์ของผู้ใช้
- **RemoteOK**: ใช้ได้ถ้าใส่ลิงก์กลับไปหน้างานของ RemoteOK และระบุชื่อเป็นแหล่งที่มา
- **Remotive**: ห้ามใช้ประกาศงานเพื่อเก็บสมัครสมาชิก/อีเมล และจำกัดราว 4 ครั้งต่อวัน → **ไม่ใช้ใน v1** (ขัดกับ product ที่ต้อง login)
- **We Work Remotely**: ข้อตกลง API ห้ามแอปที่ "แข่งหรือแทนที่" WWR และห้ามเก็บข้อมูล → **ไม่ใช้ใน v1** จนกว่าจะขออนุญาตเป็นลายลักษณ์อักษร
- **Adzuna**: ไม่ครอบคลุมไทย · Jooble / Careerjet / TheirStack: ยังยืนยันปริมาณงานไทยไม่ได้ → ไม่อยู่ใน v1
- **Chrome Web Store**: ต้องมี privacy policy, ขอสิทธิ์แคบที่สุด, ห้ามโหลดโค้ดจากภายนอก (ส่งข้อมูลไปให้ server วิเคราะห์ได้),
  การอ่านเนื้อหาหน้าเว็บต้องเป็นฟีเจอร์ที่ผู้ใช้เห็นและอธิบายชัดในหน้า store

## 4. แนวทางที่พิจารณา

| แนวทาง | ได้อะไร | เสียอะไร | ผล |
|---|---|---|---|
| A. เว็บ + วางลิงก์ + ดึงงานจากแหล่งเปิด | เร็วสุด ไม่ผิดกฎ | งานไทยต้องวางเองทีละงาน | เป็นฐานของ v1 |
| B. เว็บ + extension | เก็บงานไทยในคลิกเดียว, กรอกฟอร์มได้, ทำงานในบัญชีผู้ใช้เอง | คอมเท่านั้น, ต้องผ่านรีวิว store, ต้องซ่อมเมื่อเว็บงานเปลี่ยน | **เลือก (รวมกับ A)** |
| C. Scrape เว็บงานไทยจาก server | อัตโนมัติเต็มที่ | ผิดข้อตกลงเว็บ โดนบล็อก เสี่ยงกฎหมาย | ตัดทิ้ง |
| D. เชื่อม Gmail อ่านอีเมลแจ้งเตือนงาน | งานไทยเข้าเองโดยไม่ต้องเปิดคอม | ต้องผ่านการตรวจความปลอดภัยของ Google | เลื่อนไปก้อน 5 |
| E. แอป native | อยู่ใน store | งานสองชุด, store หักค่าสมาชิก 15–30% | เลื่อน ห่อเว็บทีหลังได้ |

ผู้ใช้เลือก: **เว็บ (ใช้บนมือถือได้) + extension ตั้งแต่เวอร์ชันแรก**

## 5. การออกแบบ

### 5.1 ภาพรวมระบบ

```
[Extension ใน Chrome] ──┐
                        ├──> [เว็บ + API (Next.js)] ──> [Supabase: สมาชิก + ฐานข้อมูล]
[เว็บบนคอม/มือถือ] ─────┘            │
                                     ├──> [Claude API: แกะประกาศ, ให้คะแนน, ghost, ปรับ resume]
[งานประจำวัน (cron)] ────────────────┘
     └─ ดึงงานจาก Greenhouse / Lever / Ashby / RemoteOK
```

Extension ไม่เรียก AI เอง ส่งเนื้อหาหน้าเว็บให้ API ของเราเสมอ (key ของ AI อยู่ฝั่ง server เท่านั้น)

### 5.2 Stack (ผมเลือกเอง ผู้ใช้ไม่ได้กำหนด)

- เว็บและ API: Next.js (App Router) + TypeScript, deploy บน Vercel
- สมาชิกและข้อมูล: Supabase (Auth + Postgres + Row Level Security + Storage สำหรับไฟล์ resume)
- AI: Claude API ใช้ผลลัพธ์แบบมีโครงสร้าง (JSON ตาม schema)
- Extension: Chrome Manifest V3, ใช้ได้กับ Chrome และ Edge
- สองภาษา: next-intl, ข้อความ UI ทั้งหมดอยู่ในไฟล์แปล
- Login: Google และอีเมล magic link

### 5.3 ข้อมูลหลัก

- **profile**: ข้อมูลที่แกะจาก resume (ทักษะ, ประสบการณ์, การศึกษา) + ความต้องการ
  (ตำแหน่ง, เงินเดือนขั้นต่ำ, ไทย/remote, ระดับ) ผู้ใช้แก้ได้ทุกช่อง
- **job**: ประกาศงานที่แกะแล้ว (ตำแหน่ง, บริษัท, ที่ตั้ง/remote, เงินเดือน, ทักษะที่ต้องการ, วันที่ลง, ลิงก์, แหล่งที่มา)
  งานจากแหล่งเปิดใช้ร่วมกันทุกคน งานที่ผู้ใช้เก็บเองเป็นของคนนั้น
- **company**: ชื่อบริษัท, ระบบรับสมัครที่ใช้ และรหัสบอร์ด
- **evaluation** (ต่อ ผู้ใช้ × งาน): คะแนนความเหมาะสม 0–100, เหตุผล, ระดับความเสี่ยง ghost, สัญญาณที่เจอ
- **application** (ต่อ ผู้ใช้ × งาน): สถานะ, บันทึก, วันที่เปลี่ยนสถานะ, resume ฉบับปรับที่ใช้
- **job_sighting**: บันทึกว่าเห็นประกาศนี้เมื่อไหร่ ใช้ตรวจการลงซ้ำ

ผู้ใช้เห็นได้เฉพาะข้อมูลของตัวเอง บังคับด้วย Row Level Security ที่ฐานข้อมูล

### 5.4 งานเข้ามาในระบบได้ 4 ทาง

1. **อัตโนมัติรายวัน**: cron ดึงประกาศจากบอร์ด Greenhouse / Lever / Ashby ของบริษัทในรายชื่อ และจาก RemoteOK
   - รายชื่อบริษัทเริ่มต้น: ผู้สร้างรวบรวมบริษัทเทคไทยและบริษัท remote ที่จ้างคนไทยได้ ราว 100–200 แห่ง
   - ผู้ใช้เพิ่มบริษัทที่สนใจได้เองด้วยการวางลิงก์หน้า careers ระบบตรวจว่าใช้ระบบไหนแล้วเพิ่มเข้ารายชื่อ
   - งานจาก RemoteOK แสดงลิงก์กลับและชื่อแหล่งที่มาเสมอ
2. **Extension**: กดเก็บจากหน้างานที่เปิดอยู่
3. **วางลิงก์** ในเว็บ: server ดึงหน้านั้นเฉพาะกรณีเป็นหน้า careers ของบริษัทหรือบอร์ดที่อนุญาต
   ถ้าเป็น JobsDB / JobThai / LinkedIn ให้แจ้งผู้ใช้ให้ใช้ extension หรือวางข้อความแทน
4. **วางข้อความประกาศ** ในเว็บ (ทางสำรองบนมือถือ)

ทุกทางจบที่ขั้นเดียวกัน: AI แกะเป็น job → ตรวจซ้ำ → ประเมิน

### 5.5 คะแนนความเหมาะสม

- กรองหยาบก่อนด้วยกฎ (ตำแหน่ง, ที่ตั้ง, ระดับ) เพื่อไม่ต้องเรียก AI กับทุกงาน
- งานที่ผ่านกรอง: AI เทียบ profile กับประกาศ ให้คะแนน 0–100 พร้อมเหตุผล 3 ส่วน: ตรงอะไร, ขาดอะไร, ควรรู้อะไร
- เก็บผลไว้ ประเมินใหม่เมื่อ profile เปลี่ยนเท่านั้น

### 5.6 ตรวจ ghost job

แสดงเป็น 3 ระดับ (ต่ำ / กลาง / สูง) **พร้อมรายการสัญญาณที่เจอเสมอ** ไม่ฟันธง

สัญญาณที่คำนวณจากข้อมูล:
- ประกาศอายุเกิน 30 / 60 วัน
- ลงซ้ำหลายรอบ (จาก job_sighting)
- ประกาศที่เก็บมาจากบอร์ดรวม แต่ไม่มีในหน้า careers ของบริษัทเอง (ตรวจได้เมื่อบริษัทอยู่ในรายชื่อ)
- บริษัทมีประกาศเปิดจำนวนมากผิดปกติเทียบกับที่เคยเห็น

สัญญาณที่ AI อ่านจากเนื้อหา:
- รายละเอียดงานกว้างและไม่ระบุทีมหรือความรับผิดชอบ
- ไม่มีช่องทางสมัครที่ชัดเจน หรือมีข้อความแบบ "เปิดรับตลอด / talent pool"

### 5.7 List งาน (หน้าหลักของเว็บ)

สถานะ: `เจอแล้ว → สนใจ → เตรียมสมัคร → สมัครแล้ว → สัมภาษณ์ → ได้ offer` และ `ไม่ผ่าน` / `ถอนตัว`

```
┌ ผีน้อย: "วันนี้เจองานใหม่ที่เข้ากับคุณ 4 งานนะ!" ─────────────────┐
│ [งานแนะนำ]  [กำลังดำเนินการ]  [ทั้งหมด]            ไทย | EN      │
├──────────────────────────────────────────────────────────────────┤
│ Senior Backend Engineer · บริษัท ก · Remote     คะแนน 88  👻ต่ำ  │
│ สมัครแล้ว · 3 วันก่อน                           [ดูรายละเอียด]   │
├──────────────────────────────────────────────────────────────────┤
│ Full-stack Developer · บริษัท ข · กรุงเทพ       คะแนน 74  👻สูง  │
│ เจอแล้ว · ประกาศมา 92 วัน, ลงซ้ำ 3 รอบ           [ดูรายละเอียด]   │
└──────────────────────────────────────────────────────────────────┘
```

- เป็นรายการแถวเรียบทั้งบนคอมและมือถือ กรองตามสถานะจากแถบข้าง (ดูข้อ 5.11)
- ผู้ใช้เปลี่ยนสถานะเอง ใน v1 ระบบเปลี่ยนให้อัตโนมัติจุดเดียว: เป็น "สมัครแล้ว" เมื่อผู้ใช้ยืนยันใน extension หลังกดส่งฟอร์ม
- ผีน้อยเตือนเมื่อสมัครไปแล้ว 7 วันยังไม่มีความคืบหน้า

### 5.8 Extension

- **สิทธิ์**: ขอเฉพาะโดเมนที่รองรับ (JobsDB, JobThai, LinkedIn Jobs, หน้าบอร์ด Greenhouse / Lever / Ashby)
  เว็บอื่นใช้ `activeTab` เมื่อผู้ใช้กดไอคอนเอง ไม่ขอ `<all_urls>`
- **บนหน้าประกาศงาน**: ผีน้อยตัวเล็กมุมจอ กดแล้วเปิดแผงข้าง แสดงคะแนน เหตุผล ความเสี่ยง ghost และปุ่ม "เก็บเข้า list"
  เนื้อหาหน้าเว็บถูกส่งให้ server ก็ต่อเมื่อผู้ใช้เปิดแผงหรือกดเก็บ ไม่ส่งเองเบื้องหลัง
- **การอ่านหน้า**: ส่งข้อความที่มองเห็นของหน้าให้ AI แกะ ไม่ผูกกับโครงสร้าง HTML ของแต่ละเว็บ
- **บนหน้าฟอร์มสมัคร** (รองรับ Greenhouse / Lever / Ashby ใน v1): ปุ่ม "ให้ผีน้อยกรอก"
  กรอกช่องมาตรฐานจาก profile, แนบ resume, ร่างคำตอบคำถามปลายเปิดจาก profile จริงเท่านั้น
  ช่องที่ AI ไม่มีข้อมูลให้เว้นว่างและไฮไลต์ **ไม่มีการกดส่งแทนผู้ใช้**
- **Login**: ใช้บัญชีเดียวกับเว็บ

### 5.9 Resume ฉบับปรับตามงาน

- AI จัดลำดับและปรับถ้อยคำจากเนื้อหาใน profile ให้ตรงกับประกาศ ห้ามเพิ่มข้อเท็จจริงใหม่
- แสดงสิ่งที่เปลี่ยนเทียบกับต้นฉบับให้ผู้ใช้ตรวจก่อนใช้
- ส่งออกเป็น PDF รูปแบบเดียวที่ระบบคัดกรอง resume อ่านได้ (คอลัมน์เดียว ไม่มีรูป)

### 5.10 Mascot ผีน้อย

ตัวละครออกแบบใหม่ของเราเอง ผู้ใช้ยืนยันหน้าตาแล้วจาก mockup (`docs/mockups/great-job-v1.html`):

- ผีสีดำตัวกลม สีเรียบ ไม่มีแสงเงาและไม่มีเส้นขอบ ไล่จากเทาเข้มด้านบนลงดำด้านล่าง
- หน้าเป็นแถบขาวมนขนาดเล็ก ตาเป็นวงรีแนวตั้งเล็กสองจุดอยู่ชิดกัน ไม่มีแก้มและไม่มีปากในท่าปกติ
- ชายผ้าเป็นคลื่นสะบัดไปด้านขวา มีปอยผมบนหัว แขนเล็กสองข้าง ลอยเหนือเงาบนพื้น
- อารมณ์บอกด้วยรูปตา ท่าทาง และของประกอบ (แว่นขยาย หมวกปาร์ตี้ ป้าย "สู้ ๆ นะ")
- โหมดมืด: ตัวผีสว่างขึ้นหนึ่งระดับเป็นเทาเข้ม เพื่อไม่ให้กลืนกับพื้นหลัง
- **วิธีทำ**: ยก SVG และ animation จาก mockup มาเป็น component เดียว `<Ghost mood="..." size="..." />`
  ใช้ทั้งในเว็บและ extension ไม่ต้องวาดใหม่
- **ท่าและอารมณ์ใน v1**

| mood | ท่า | ใช้เมื่อ |
|---|---|---|
| idle | ลอยขึ้นลงช้าๆ กะพริบตา | ปกติ |
| wave | โบกมือ | ทักทาย, เริ่มใช้งานครั้งแรก |
| searching | ถือแว่นขยาย มองซ้ายขวา | กำลังดึง/แกะงาน |
| thinking | เอียงตัว มีจุดสามจุด | AI กำลังประเมิน |
| happy | เด้ง ตายิ้ม | เจองานคะแนนสูง, เก็บงานสำเร็จ |
| celebrate | หมุนตัว มีกระดาษสีโปรย | ได้สัมภาษณ์, ได้ offer |
| spooked | ตัวสั่น ตาโต | เจองานเสี่ยง ghost สูง |
| sad | ตัวห่อ ตาตก | สถานะ "ไม่ผ่าน" |
| cheer | ชูป้ายให้กำลังใจ | หลัง "ไม่ผ่าน", เตือนติดตามผล |
| sleepy | หลับ มี z ลอย | ไม่มีงานใหม่, ไม่ได้เข้านาน |

- เคารพการตั้งค่า "ลดการเคลื่อนไหว" ของเครื่อง: แสดงภาพนิ่งของอารมณ์นั้นแทน
- ผีน้อยพูดสั้นๆ ผ่านกล่องข้อความ ข้อความมาจากไฟล์แปล ไม่ได้ให้ AI แต่งสด

### 5.11 แนวทาง UI

ผู้ใช้เลือกแนวแอปเอกสารที่เรียบและโล่งแบบ Craft (อ้างอิงจาก Mobbin) และยืนยันจาก mockup แล้ว
ให้ยึด mockup เป็นต้นแบบของสี ระยะ และองค์ประกอบ:

- พื้นขาวโล่ง แถบข้างอยู่บนพื้นเดียวกับเนื้อหาโดยไม่มีเส้นกั้น รายการที่เลือกเป็นแถบเทาอ่อน
- รายการงานเป็นแถวเรียบ ไม่ใช่การ์ด: วงแหวนคะแนนซ้าย ชื่องานและบริษัทกลาง เงินเดือน อายุประกาศ และป้าย ghost ขวา
- หัวหน้า: ปุ่ม + วงกลมดำคู่กับชื่อหน้า ตัวกรองเป็นแท็บเล็ก อันที่เลือกเป็นสีฟ้า
- แถบข้างนับจำนวนงานตามสถานะ
- หน้ารายละเอียดงานเป็นเอกสารหนึ่งแผ่นบนพื้นเทา แผงขวาสำหรับสถานะและปุ่ม เปลี่ยนสถานะแล้วผีน้อยเปลี่ยนท่าตาม
- ผีน้อยเป็นปุ่มลอยมุมขวาล่างทุกหน้า
- Extension เป็นหน้าต่างเล็กลอยมุมโค้ง
- สีฟ้าสีเดียวสำหรับสิ่งที่กดได้ ฟอนต์ Anuphan รองรับโหมดสว่างและมืด
- มุมมองกระดานลากการ์ด (ข้อ 5.7) เลื่อนออกจาก v1: mockup ที่ยืนยันใช้รายการแถวเรียบกับแถบสถานะด้านข้างแทน

### 5.12 ความเป็นส่วนตัว

- Resume และ profile เป็นข้อมูลส่วนบุคคลตาม PDPA: ขอความยินยอมตอนสมัคร, มีปุ่มส่งออกและลบบัญชีพร้อมข้อมูลทั้งหมด
- ต้องมี privacy policy สองภาษาก่อนส่ง extension เข้า store
- เนื้อหาที่ส่งให้ AI: resume และข้อความประกาศงานเท่านั้น

### 5.13 การคุมค่าใช้จ่าย AI (ก่อนมีระบบจ่ายเงิน)

- เพดานต่อผู้ใช้ต่อวัน: จำนวนการประเมินงานและการปรับ resume (ตัวเลขเริ่มต้นผู้สร้างกำหนด ปรับได้จาก config)
- งานจากแหล่งเปิดแกะครั้งเดียวใช้ร่วมกันทุกคน
- เกินเพดานแล้วผีน้อย (sleepy) บอกว่าพรุ่งนี้มาใหม่

## 6. ลำดับการสร้าง

1. โครงเว็บ, สมาชิก, สองภาษา, component ผีน้อย (idle / wave / thinking)
2. อัปโหลด resume → profile
3. วางลิงก์/ข้อความ → แกะงาน → คะแนน → ghost → list งานและสถานะ
4. ดึงงานอัตโนมัติรายวัน + หน้างานแนะนำ
5. Extension: เก็บงานและแสดงคะแนน
6. Resume ฉบับปรับ + extension กรอกฟอร์ม
7. อารมณ์ผีน้อยที่เหลือ, PDPA, privacy policy, ส่ง store

แต่ละขั้นจบแล้วใช้งานได้จริงด้วยตัวเอง

## 7. การตรวจว่าใช้ได้

- ชุดทดสอบ AI: ประกาศงานจริง 30 ชิ้น (ไทย/อังกฤษ, หลายแหล่ง) ตรวจว่าแกะข้อมูลถูก
  และ resume ตัวอย่าง 5 ชุดตรวจว่าคะแนนเรียงลำดับสมเหตุผล
- ทดสอบว่า resume ฉบับปรับไม่มีข้อเท็จจริงที่ไม่อยู่ใน profile
- ทดสอบว่าผู้ใช้ A อ่านข้อมูลผู้ใช้ B ไม่ได้
- ทดสอบสัญญาณ ghost ที่คำนวณจากข้อมูลด้วยข้อมูลจำลอง

## 8. ที่ปล่อยให้ผู้สร้างตัดสิน

- โครงสร้างตารางและชื่อคอลัมน์โดยละเอียด
- รุ่นของ Claude ที่ใช้ในแต่ละงาน และการเขียน prompt
- รายชื่อบริษัทเริ่มต้น
- หน้าจอที่ mockup ยังไม่มี (login, ตั้งค่า, profile, list ว่าง) ให้ออกแบบตามแนวเดียวกับ mockup
- ไลบรารีแกะไฟล์ PDF/DOCX และสร้าง PDF
- น้ำหนักของแต่ละสัญญาณ ghost และเกณฑ์แบ่ง 3 ระดับ (ปรับจากชุดทดสอบ)

## 9. ข้อตัดสินเพิ่มเติมหลังผู้ตรวจอ่าน (ผมตัดสินเอง ผู้ใช้แก้ได้)

1. **งานที่เก็บผ่าน extension ไม่ใช้ร่วมกันข้ามผู้ใช้** เนื้อหาประกาศเป็นของคนที่เก็บเท่านั้น
   สิ่งเดียวที่ใช้ร่วมกันคือ job_sighting แบบไม่มีเนื้อหา: รหัสย่อ (hash) ของ บริษัท+ตำแหน่ง, โดเมนแหล่งที่มา, วันที่เห็น
   พอสำหรับตรวจการลงซ้ำและอายุประกาศ โดยไม่กลายเป็นฐานข้อมูลที่ scrape มา
2. **ขนาดที่ออกแบบรองรับ**: ช่วงทดลองไม่เกิน 200 ผู้ใช้ ใช้ cron ธรรมดา ไม่ต้องมีระบบคิว
   การประเมินอัตโนมัติรายวันทำเฉพาะผู้ใช้ที่เข้าใช้ใน 7 วันล่าสุด ไม่เกิน 20 งานต่อคนต่อวัน และไม่นับรวมกับเพดานที่ผู้ใช้กดเอง
3. **การวางลิงก์**: server ดึงเฉพาะโดเมนของ Greenhouse / Lever / Ashby เท่านั้น
   ลิงก์อื่นทุกชนิดให้ผู้ใช้วางข้อความหรือใช้ extension
4. **การแจ้งเตือน**: ในแอปเท่านั้น (ป้ายตัวเลขและข้อความจากผีน้อย) ไม่มีอีเมลหรือ push ใน v1
5. **ผีน้อย**: ใช้ SVG จาก mockup ที่ผู้ใช้ยืนยันแล้ว ไม่มีไฟล์จากนักออกแบบ
6. **LinkedIn อยู่ในรายการที่รองรับตอนเปิดตัว** extension อ่านหน้าเฉพาะเมื่อผู้ใช้กดเอง ไม่คลิกหรือเปิดหน้าแทนผู้ใช้
   จึงไม่เข้าข่าย anti-goal เรื่องความเสี่ยงบัญชี และมีสวิตช์ถอดออกได้ (ดูข้อ 10)
7. **Privacy policy และข้อความขอความยินยอม**: ผู้สร้างร่างให้สองภาษา เจ้าของ product ต้องให้ผู้รู้กฎหมายตรวจก่อนเปิดจริง

**สิ่งที่เจ้าของ product ต้องเตรียม (บัญชีเป็นชื่อเจ้าของ)**: Supabase, Vercel, Anthropic API key,
Google Cloud (สำหรับ login ด้วย Google), บัญชีนักพัฒนา Chrome Web Store, โดเมน

## 10. ความเสี่ยงที่รู้

- LinkedIn อาจมองว่า extension ที่อ่านหน้างานขัดข้อตกลงผู้ใช้ แม้จะอ่านเฉพาะเมื่อผู้ใช้กดเอง
  ถ้าถูกร้องเรียน ให้ถอด LinkedIn ออกจากโดเมนที่รองรับได้โดยไม่กระทบส่วนอื่น
- บริษัทเทคไทยที่ใช้ Greenhouse / Lever / Ashby อาจมีไม่มาก งานไทยใน v1 จึงพึ่ง extension เป็นหลัก
- รีวิว Chrome Web Store อาจใช้เวลาหลายวันและถูกตีกลับได้ เว็บต้องใช้งานได้ครบโดยไม่มี extension
